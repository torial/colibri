# colibri in V

A port of colibri to V, one library at a time, each checked against the C original by a differential test
(same inputs, outputs compared bit for bit). Background and measurements: `../docs/v-port-exploration.md`.

| V module | C original | status | check |
|---|---|---|---|
| `cjson` | `c/json.h` | done, behaviour-identical (see the header comment for the one deliberate difference) | `tests/json_diff/run.sh [N] [seed]`: 20,000+ documents, tree dumps identical; `v test cjson` |
| `safetensors` | `c/st.h` | tensor table with the C code's header validation; search path of directories (SPLIT); the `model.safetensors.index.json` overlay rule; `colibri.fmt` stamps; read mirrors on other drives; f32 / scale / raw / capped / slice / physical-range / replica-range (O_DIRECT) readers; prefetch and readahead advice; per-tensor and per-shard read-only maps; the missing-tensor report; GGUF folders (`gguf.json`) with the ten architecture name maps, fused-expert splitting, the colibri packed-expert container and the DSpark head. POSIX only (Windows overlapped handles and macOS `F_NOCACHE` twins are not ported) | `tests/st_diff/run.py [N] [seed]`: 4,000+ model directories (hostile headers included) identical; `tests/st_ext/run.py [N] [seed]`: generated search paths, overlays, stamps, mirrors, GGUF folders (every architecture, split parts, packed experts, 17 kinds of broken header) and ~60 operations per case, exit status, stdout and stderr identical (small and default pread chunk, O_DIRECT on and off); every f16 / bf16 / e8m0 input identical; `v test safetensors` |

| `glm` | the unquantized (`colibri CAP 16 16`) path of `c/colibri.c`, GLM-5.2 (`glm_moe_dsa`) | MLA attention in latent space (low-rank query, shared KV latent with a decoupled interleaved-RoPE key, the engine's 8-lane score dot), leading dense SwiGLU layers, sigmoid router with a selection bias, top-k, renormalization, routed scale, f32 routed experts through an LRU cache in the engine's union order, shared expert, prefill + decode, greedy generation. int8 per-row weights too (`open_bits(dir, cap, 8)`: the layer matrices and experts quantized at load as `quantize_rows` does, run through the float-activation kernels, i.e. `IDOT=0 ./colibri CAP 8 8`). | `tokenizer` | `c/tok.h` | BPE load / encode / decode / id_of for the cl100k, o200k, tekken, kimi, gpt2, deepseek (and qwen digit-grouping) pre-tokenizers; Unicode class tables generated from `c/tok_unicode*.h` | `tests/tok_diff/run.py [N] [seed]`: 1,600+ texts over 8 families, ids and decoded bytes identical; every code point's class set identical (`c_uni` / `v_uni`); `v test tokenizer` |

`v/run_all.sh` runs everything. Next in order: `tok.h` (tokenizers), `sample.h`, `numa_topo.h`, then the rest of `st.h`. Kernels stay C behind `fn C.` bindings.
Run the differential tests with a V compiler and gcc on PATH.

## Building and running

`./run_all.sh [scale]` builds `kernels/libcolikern.a` and runs every unit test and differential test above. It needs `gcc`,
`python3` and a V compiler on `PATH`. Modules that do not touch the compute kernels (`cjson`, `safetensors`, `gguf`,
`tokenizer`, `sample`) build with V's default compiler; a program that imports `kernels` needs `v -cc gcc` and
`kernels/build.sh` run first.

## Sanitizers

Every differential test can run the C original under AddressSanitizer + UndefinedBehaviorSanitizer: `SAN=1 ASAN_OPTIONS=detect_leaks=0
python3 tests/st_ext/run.py 250 12` (likewise `st_diff`, `tok_diff`, `sample_diff`, and `SAN=1 tests/json_diff/run.sh`). The hostile
corpora then double as a fuzzer for the C parsers; a sanitizer report in the C shows up as a mismatch.
